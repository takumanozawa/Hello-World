# ICT施工Stage2管理システム - システム設計書

## 1. システム概要

### 1.1 目的
河道掘削工事向けの統合管理システムで、複数現場の施工データをリアルタイムに収集・分析し、継続的な改善を実現する。

### 1.2 適用範囲
- 河道掘削工事（複数現場同時管理）
- 重機・ダンプトラックの稼働管理
- 工程管理・リソース最適化
- 施工データ分析・レポート生成

## 3. 技術スタック

### 3.1 バックエンド
| 項目 | 技術 | 理由 |
|------|------|------|
| 言語 | Python 3.11+ | データ分析・最適化アルゴリズムに強い |
| フレームワーク | FastAPI | 高速、型安全、WebSocket対応 |
| ORM | SQLAlchemy 2.0 | 型安全、async対応 |
| 非同期処理 | Celery + Redis | バッチ処理、レポート生成 |
| WebSocket | FastAPI WebSocket | リアルタイム位置情報配信 |

### 3.2 フロントエンド
| 項目 | 技術 | 理由 |
|------|------|------|
| 言語 | TypeScript | 型安全、大規模開発向け |
| フレームワーク | React 18 | コンポーネント再利用性、エコシステム |
| 状態管理 | Redux Toolkit | 複雑な状態管理に対応 |
| UI | Material-UI (MUI) | 完成度の高いコンポーネント |
| 地図表示 | Leaflet + React-Leaflet | オープンソース、軽量 |
| グラフ | Recharts | React向け、カスタマイズ性高い |
| ガントチャート | DHTMLX Gantt | 高機能、商用利用可 |

### 3.3 モバイル
| 項目 | 技術 | 理由 |
|------|------|------|
| フレームワーク | React Native | Webと技術スタック共通化 |
| ナビゲーション | React Navigation | 標準的なルーティング |
| オフライン同期 | WatermelonDB | SQLite、高速同期 |

### 3.4 データベース
| 項目 | 技術 | 理由 |
|------|------|------|
| メインDB | PostgreSQL 15 | JSONB対応、PostGIS（地理情報） |

### 3.5 インフラ・DevOps

## 4. データベース設計（概要）

### 4.1 主要テーブル

#### 現場管理
- **sites**: 現場マスタ
- **site_tasks**: 工程タスク
- **site_daily_reports**: 日報

#### リソース管理
- **vehicles**: 車両マスタ（ダンプ、重機）
- **workers**: 作業員マスタ
- **resource_assignments**: リソース配置

#### 位置情報・運行管理
- **gps_positions**: GPS位置データ（TimescaleDB）
- **vehicle_cycles**: 運搬サイクル
- **cycle_segments**: サイクル区間（積込、運搬、荷降ろし等）

#### アラート・通知
- **alert_rules**: アラートルール定義
- **alerts**: アラート発生履歴
- **notifications**: 通知履歴

#### シミュレーション
- **simulations**: シミュレーション設定
- **simulation_results**: シミュレーション結果

詳細なスキーマは `docs/DATABASE_SCHEMA.md` を参照

## 5. 主要機能とAPI設計

### 5.1 運行管理API
```
POST   /api/v1/gps/positions        # GPS位置データ登録
GET    /api/v1/vehicles/{id}/track  # 車両の移動軌跡
GET    /api/v1/cycles/current       # 現在のサイクル状況
GET    /api/v1/cycles/statistics    # サイクル統計
```

### 5.2 工程管理API
```
GET    /api/v1/sites                # 現場一覧
GET    /api/v1/sites/{id}/tasks     # 工程タスク一覧
PUT    /api/v1/tasks/{id}/progress  # 進捗更新
GET    /api/v1/tasks/{id}/gantt     # ガントチャート データ
```

### 5.3 リソース最適化API
```
GET    /api/v1/resources/current    # 現在の配置状況
POST   /api/v1/resources/optimize   # 最適配置計算
PUT    /api/v1/resources/assign     # リソース割当
```

### 5.4 シミュレーションAPI
```
POST   /api/v1/simulations          # シミュレーション実行
GET    /api/v1/simulations/{id}     # 結果取得
GET    /api/v1/simulations/compare  # 実績比較
```

### 5.5 アラートAPI
```
GET    /api/v1/alerts               # アラート一覧
POST   /api/v1/alerts/{id}/ack      # アラート確認
WS     /ws/alerts                   # アラートリアルタイム配信
```

### 5.6 レポートAPI
```
GET    /api/v1/reports/daily        # 日報取得
GET    /api/v1/reports/weekly       # 週報取得
POST   /api/v1/reports/export       # Excel出力
```

## 6. 非機能要件

### 6.1 性能要件
| 項目 | 要件 |
|------|------|
| GPS位置データ処理 | 100台 × 10秒間隔 = 600件/分を処理 |
| ダッシュボード応答 | 2秒以内 |
| WebSocket遅延 | 1秒以内 |
| レポート生成 | 30秒以内（1ヶ月分） |

### 6.2 可用性
- 稼働時間: 99.5%（年間43.8時間のメンテナンス許容）
- バックアップ: 日次フルバックアップ、WALアーカイブ
- 障害復旧: 4時間以内（RTO）

### 6.3 セキュリティ
- 認証: JWT（Access Token + Refresh Token）
- 通信: TLS 1.3
- データ暗号化: DB列暗号化（個人情報）
- アクセス制御: RBAC（管理者、監督、作業員）

### 6.4 拡張性
- 同時接続: 500ユーザー
- データ保存期間: 5年分
- 現場数: 100現場まで拡張可能
